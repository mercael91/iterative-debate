# Итерационные дебаты

Процесс проверки решения спором нескольких РАЗНЫХ семейств моделей: не «ещё один план»,
а отброшенные идеи, вердикт по каждому спорному пункту и ОДНО действие. Скилл даёт
инварианты, формат, условие остановки и драйвер, который ведёт круги и пишет стенограмму.
Зависимостей нет: только Python 3 stdlib и OpenAI-совместимые chat-completions эндпоинты.

## Install

Скилл ставится одним файлом, драйвер лежит в репозитории:

```bash
hermes skills install https://raw.githubusercontent.com/mercael91/iterative-debate/main/SKILL.md
git clone https://github.com/mercael91/iterative-debate.git
cd iterative-debate && python scripts/iterative_debate.py --help
```

## When to Use — когда применять

- Решение с ценой ошибки: архитектура, стратегия, цена, приоритет, «делать ли вообще».
- План выглядит гладким, и оспорить его некому — нужен контрпример, а не согласие.
- Своё заявление надо проверить на ШИРИНУ: обобщение по одному случаю — самый частый
  подтверждающийся класс ошибок.

Не применять:

- Факты не собраны. Дебаты не знают того, чего им не дали, и уверенно наврут.
- Есть живой ревьюер или аудитор с доступом к коду — он дешевле и точнее.
- Рутинная правка с тестом на руках: тест проверяет, дебаты обсуждают.

## Три режима

| Режим | Когда | Что на выходе |
|---|---|---|
| Стратегические дебаты сетей | Вопрос без кода: деньги, цена, приоритет | Итог-файл + одно выбранное действие |
| Круговой аудит | Есть система, нужен внешний взгляд; правки между кругами | Критика по кругам + ответ «что исправлено», история в JSONL |
| Встроенный движок | Решение внутри пайплайна, перед действием | Вердикт approve / caution / reject + альтернатива |

Драйвер из репозитория закрывает первый режим. Круговой аудит — тот же цикл, но между
кругами вы применяете фиксы и записываете, что сделано: критик не повторяет закрытые
пункты (это прямое правило в промпте). Встроенный движок отличается тем, что вердикт
возвращается в код, а не в файл, и обязан быть блокирующим.

## Инварианты

1. **Разные семейства моделей.** Одна сеть, спорящая сама с собой, выдаёт красивые
   формулировки одной и той же мысли. Роли конфликтуют по ИНТЕРЕСУ, не по тону.
2. **Факты заранее, с запретом выдумывать другие цифры.** Разрешать уточнять смысл
   приведённых чисел, но не заменять их.
3. **Жёсткий формат ответа, одинаковый у всех:** `КРИТИКА:` / `НОВЫЙ АРГУМЕНТ:` (один,
   с числом или сроком) / `ПОЗИЦИЯ:` (одно действие), не длиннее 160 слов. Без него
   нечего сравнивать и не видно схождения.
4. **Окно контекста, а не вся стенограмма.** 4 последних реплики чужих участников.
5. **Стенограмма после КАЖДОГО круга.** Долгий прогон умирает по таймауту.
6. **Условие остановки задано до запуска.** Останавливаемся, когда выполнено любое:
   все написали «НОВЫЙ АРГУМЕНТ: нет» на круге ≥ 4; **два круга подряд никто не назвал
   новой цифры** (застой — дальше идёт переубеждение, а не поиск ходов); исчерпан лимит
   кругов. Сходиться можно только когда ответили ВСЕ участники: иначе один живой объявит
   согласие за мёртвого.
7. **Вердикт по каждому спорному пункту:** подтверждено / опровергнуто / не проверено.
   «Не проверено» — честный ответ; догадка в итог не идёт.
8. **Один прогон — один вопрос.** Смена рамки по ходу = новые дебаты.

## Как запускать

Тема и факты — в отдельном файле: вопрос, числа, правила владельца, что уже умеем.
Ключи — в окружении или в `--env-file` (можно передать несколько).

```bash
# 1. сети живы? пробный вызов, тело ошибки видно сразу
python scripts/iterative_debate.py --probe --env-file .env --config actors.json

# 2. промпт без вызовов: видно роли, факты и список запрещённых позиций
python scripts/iterative_debate.py --topic-file topic.md --dry-run --config actors.json \
       --rejected rejected.txt

# 3. боевой прогон — в фоне с уведомлением, не в терминале
python scripts/iterative_debate.py --topic-file topic.md --config actors.json \
       --env-file .env --out-dir out --rejected rejected.txt
```

По умолчанию 10 кругов и финальное голосование. Дольше 10 кругов имеет смысл, только если
на каждом круге появляются новые числа; `--no-vote` отключает бюллетень, `--rounds N`
поднимает лимит. Файл `--rejected` — строки с уже отклонёнными позициями: они уходят в промпт
каждого участника, чтобы не предлагались повторно.

Роли задаются конфигом (шаблон — `templates/actors.example.json`): список объектов
`{name, base, key_env, model, role}`. Правило: чем важнее вопрос, тем важнее расхождение
семейств; дешёвая модель уместна для роли, но не для вердикта.

Критерий готовности: `--probe` говорит «живых сетей: N из N», `--dry-run` печатает N разных
системных промптов и общий вопрос.

## Как читать результат

- **Схождение vs вырождение.** К 12–15 кругу модели начинают повторять один аргумент
  разными словами — это сигнал к остановке, а не к ещё десяти кругам.
  `converged_at: null` при лимите кругов означает «сошлись по лимиту», а не «согласились».
- **Согласие на первом круге** — признак слишком узкой рамки, а не силы идеи.
- Позиции без числа, срока или адресата — отбрасывать.
- Вечные идеи («продай услугу в чужие issues», «сделай скидку за пробу») всплывают
  почти всегда. Отклонять прямо в итоговом документе, иначе вернутся в следующем прогоне.
- Враг — не спор, а гладкий текст. Если все согласились быстро, рамка слишком тесная.

## Финальное голосование

После последнего круга драйвер собирает предложенные действия, схлопывает одинаковые
(одно и то же дело разными словами — один вариант), нумерует и спрашивает каждого участника:

```
ВЫБОР: <номер>
ПРИЧИНА: <до 20 слов>
УВЕРЕННОСТЬ: <0..1>
```

Побеждает большинство; при равенстве — вариант с большей средней уверенностью. Если вариантов
меньше двух (все предлагали одно и то же) или голосов нет — в стенограмме прямо написано
«решения нет, выбор за человеком». Голосование выбирает ДЕЙСТВИЕ, а не истину, и не отменяет
вердикты «подтверждено / опровергнуто / не проверено».

## Лимиты частоты, подмена сети и судья

- **Бесплатные пулы считают запросы в минуту.** У OpenRouter для моделей `:free` — 20 запросов
  в минуту и 50 в сутки, а после ≥ $10 купленных кредитов — 1000 в сутки; лимит общий на аккаунт,
  новые ключи его не увеличивают (по документации провайдера). Три актора × 10 кругов = 30 вызовов,
  упереться легко: `--min-interval 3.5` держит зазор между вызовами, а `429` переживает ожидание
  по `Retry-After`. Такой сбой НЕ считается мёртвой сетью — участник жив, он упёрся в квоту.
  Из РФ OpenRouter отдаёт `403` и на `/models`, и на `/chat/completions` — нужен живой шлюз или VPN.
- **Роутер может подменить сеть молча.** Драйвер читает поле `model` из ответа: если оно не
  совпадает с запрошенным, в стенограмме появляется `⟪сеть: X вместо Y⟫`, а в `debate_last.json`
  растёт `model_mismatches`. Без этой проверки «ответ Клода» может оказаться ответом другой модели.
- **Судья — отдельная роль, а не участник.** `--judge judge.json` (один актор) забирает финальный
  вердикт: он видит список вариантов и обязан выбрать один. Это снимает самоголосование
  («я предложил — я и выбрал»). На роль судьи — самая сильная доступная сеть: слабая модель
  7–8B боится отказывать и выдаёт «осторожно» вместо решения.

## Грабли (все наблюдавшиеся)

- **Дебаты не знают фактов, которых им не дали.** Двадцать кругов могут уверенно спорить
  о «неоплаченных заказах», которые на самом деле оплачены. Порядок: живые данные
  (журналы, страницы, чат) → дебаты → решение.
- **Слабая модель не даёт вердикт.** Малый судья (7B локально) на десяти темах выдал
  «осторожно» вместо «да/нет»: enrich-rate 73 %, reject-rate 0 %. Вердикт отдавать сильной
  сети, а слабую использовать только для аргументов.
- **Критик не видит оригинал.** Однажды пропустил заглушку `+8/−401`. В промпт критика —
  исходный файл (крышка ~4 КБ) и правило отклонять заглушки и массовые удаления.
- **Молчаливая подмена сети.** Прокси тихо отваливался, и первые раунды отвечала другая
  модель. Смотреть, КТО ответил, а не только текст.
- **Reasoning съедает бюджет.** Наблюдалось: модель вернула реплику из одного символа («К»)
  с `finish_reason=length` при `max_tokens=300` — 298 токенов ушли в рассуждение. Драйвер
  поднимает лимит лестницей 700→1600→4000 (или `--max-tokens N` → N, 2N, 4N).
- **Квоты шлюзов кончаются молча.** `409 QUOTA_EXHAUSTED` на всех моделях шлюза = пакет
  исчерпан: лечится оплатой или сменой сети, а не перебором моделей. Поэтому `--probe`
  печатает код и текст ошибки, а не только «сбой».
- **Мёртвая сеть превращает дебаты в монолог.** Выживший участник начинает комментировать
  сам сбой. Драйвер останавливается после двух сбоев подряд; стенограмма из ошибок —
  не результат дебатов.
- **JSON-вердикт ломается** на управляющих символах и обрезке — гвард + повтор ×4, иначе
  «невалидный JSON» вместо решения.
- **Дебаты могут быть декоративными.** `reject` внутри `except: pass` не блокирует патч.
  Если вердикт должен останавливать действие — проверить наличие `return`/`continue`.
- **Время.** У reasoning-моделей реплика идёт 20–60 с: замер — 5 кругов × 2 роли ≈ 8 минут.
  Двадцать кругов × три роли — это десятки минут, отсюда правило «только в фоне».

## Пример реального прогона

Разбор одного прогона на 20 кругов (обезличенный) — в `docs/case-study.md` репозитория.
Коротко, что он показал: один и тот же факт читается ролями противоположно; adversarial-роль
к 13–16 кругу съезжает в согласие; отклонённая идея возвращается 6–7 раз; цены рождаются
внутри спора и потом цитируются как данность; формальное схождение — 1 реплика из 60;
данные, которых не дали, дебаты не восстановят.

## Проверка (что значит «сработало»)

- [ ] Стенограмма на диске (md + `debate_last.json`), итог-файл написан.
- [ ] У каждого спорного пункта вердикт: подтверждено / опровергнуто / не проверено.
- [ ] Остановка объяснена: сошлись на круге N либо исчерпан лимит кругов.
- [ ] Ни одна принятая позиция не осталась без числа, срока или адресата.
- [ ] Принятое действие отличается от того, что было ДО дебатов. Если нет — дебаты были
      декоративными, и это надо сказать прямо.
